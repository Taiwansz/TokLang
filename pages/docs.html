TokLang

TokLang é um middleware de compressão de prompts que atua como intermediário invisível entre o usuário e qualquer modelo de linguagem. Você escreve normalmente; ele comprime automaticamente.

A economia típica é de 65–85% em tokens, sem nenhuma mudança na qualidade da resposta do modelo.

Princípio central: O usuário nunca vê ou toca na notação TokLang. Ela opera completamente em segundo plano.

Quickstart

Instale o SDK e faça sua primeira compressão em menos de 5 minutos:

# instalar
npm install toklang

# uso básico
import { compress } from 'toklang'

const result = await compress("Bom dia! Pode fazer uma API em Node?")
// → "cr $js #api"

console.log(result.compressed) // cr $js #api
console.log(result.savings) // 0.71 (71%)

Para integrar como middleware transparente no seu pipeline:

import { TokLangMiddleware } from 'toklang'

const client = new TokLangMiddleware({
  target: 'openai', // ou 'anthropic' | 'gemini'
  apiKey: process.env.OPENAI_KEY,
  tokLangKey: process.env.TOKLANG_KEY
})

// use exatamente como o SDK original
const response = await client.chat.completions.create({
  model: 'gpt-4o',
  messages: [{ role: 'user', content: userMessage }]
})

Como funciona

O pipeline completo tem quatro etapas:

1. INPUT → prompt natural do usuário
2. COMPRESS → motor TokLang → notação comprimida
3. EXPAND → expansor → linguagem natural limpa
4. OUTPUT → enviado ao modelo de destino

A etapa 3 garante que o modelo nunca receba a notação TokLang — apenas um prompt limpo e preciso em linguagem natural.

TokLang vs. Prompt Caching

Provedores de LLM como Anthropic (Claude), OpenAI e Google (Gemini) já oferecem Prompt Caching nativo para reduzir custos de prompts repetidos. Então, quando o TokLang realmente compensa?

Diferença fundamental: Prompt Caching otimiza a repetição exata do contexto (estático). O TokLang otimiza o conteúdo variável (dinâmico) de cada chamada individual.
RecursoPrompt Caching NativoTokLang Middleware
Escopo da Otimização Apenas prefixos estáticos idênticos (ex: system prompt longo, base de conhecimento). Qualquer prompt individual dinâmico, independente de ser inédito ou repetido.
Tamanho Mínimo Exige prompts muito longos para ativar (geralmente > 1024 ou 2048 tokens). Sem tamanho mínimo. Funciona e economiza mesmo em prompts de 15 tokens.
TTL / Expiração O cache expira rapidamente (5 a 10 minutos de inatividade) e você paga o preço cheio na recriação. Permanente. A economia é aplicada diretamente na transmissão, sem depender de estado ou tempo.
Agnóstico a Provedores Não. Cada provedor tem sua regra, sintaxe de cabeçalho e limites de API diferentes. Sim. A compressão acontece no seu backend antes de ir para qualquer provedor (OpenAI, Claude, etc).

Quando usar cada um?

  • Use Prompt Caching Nativo quando: você tem uma base de dados de contexto estática enorme (ex: um livro de 100k tokens ou documentação completa da empresa) que é enviada repetidamente por vários usuários seguidos a cada poucos minutos.
  • Use TokLang quando: seus usuários enviam perguntas dinâmicas e variadas de tamanhos pequeno a médio, onde cada chamada possui instruções, saudações, códigos específicos e termos variados, ou quando você deseja economizar em 100% das requisições de forma constante e previsível.
  • Use Ambos combinados: O TokLang pode comprimir o system prompt estático (que é armazenado em cache no provedor pelo menor preço possível) E comprimir o input variável de cada usuário, proporcionando a máxima eficiência de custo possível na arquitetura de IA.

Sintaxe

A gramática TokLang segue um formato posicional com separadores por ponto-e-vírgula:

AÇÃO $LANG @FRAMEWORK #ESTRUTURA; tarefa; in[params]; modificadores

Apenas a AÇÃO é obrigatória. Todos os demais campos são opcionais e posicionais.

Separador ; divide os blocos lógicos do prompt. A ordem importa: ação+contexto técnico → tarefa → parâmetros → modificadores.

Ações
